## Risks

**US-22-01, Nothing a customer reads is locked in code.** The epic wide guarantee that no customer facing string needs a code change owns the theme level string catalogue that no other E22 story covers, and P-005 confirms CoreX contributes no commerce or content layer to lean on, so 5 points is thin for the sweep plus the AC-20 unaided client test.

**US-22-02, Home page sections.** A home section manager carrying per section content, media, calls to action, links, ordering and independent language copies has no WooCommerce or WordPress base once the block editor is excluded, so 3 points covers neither the admin surface nor the storefront rendering.

**US-22-03, Show and hide sections.** Once the section manager from US-22-02 exists, hide and show is a per section flag plus a render guard, so 3 points is more than the work, and Stage 4 already runs at 68 points a week.

**US-22-04, Category and brand page content.** Category description and image are native term fields and brands are a Woo taxonomy, so this is term meta on existing screens, but no probe covers whether the translation plugin carries term meta such as a banner or hero image as well as it carries the term name.

**US-22-05, Collection content and ordering.** Woo menu_order is a single global catalogue ordering, so a manual product order per collection needs its own storage and its own query layer, and 3 points does not cover the collection entity, the ordering interface and the storefront query together.

**US-22-06, Navigation and footer.** WordPress menus give a base for the menu itself, but the mega menu structure, the footer column manager and the AC 3 report of a link present in one language and missing in the other have no native equivalent, and the right to left behaviour of the CoreX header, nav and footer is still unproven.

**US-22-07, Static and policy pages.** Pages, policy pages and the FAQ are editable in WordPress as it ships and the translation plugin covers the per language half, so the only real work is the AC 3 consistency between the return policy page and the return window configured in US-13-02.

**US-22-08, Promotional banners and campaign pages.** Banner creation with scheduling, page targeting and removal is a build with no Woo base, and AC 2 assembly of a campaign page from existing components has to reuse the US-22-02 section manager, so 5 points in Stage 5, which already runs at 92 points a week, is thin.

**US-22-09, Content maintained independently in both languages.** P-006 proves the plugin keeps product, variation and attribute data linked as one translation group, which settles the mechanism, but it does not cover the custom content areas this epic creates, and AC 3, a report of content missing in one language, only works once every home section, collection, menu and footer structure is registered with the plugin.

**US-22-10, Preview before publish.** WordPress preview and the draft state apply to posts and pages only, so previewing home sections, term meta, navigation and footer needs a draft versus published content store that no other story owns, and at 3 points this is the most under pointed item in the epic.

**US-22-11, Revert a content change.** WordPress revisions cover post content only, so reverting a section, a menu, a footer or term meta rides on the same versioned store as US-22-10, and 1 point does not cover it even though the actor and timestamp come free from the audit log at section 7 row 14.

## Open questions

- **US-22-01.** Which storage layer holds the admin editable strings for theme chrome, labels and error messages. No SSC id names one, and plugins.json registers no need for a field or content framework.
- **US-22-01.** AC-20 requires the client to edit unaided. No probe or wireframe yet defines the admin surface they would use, and the obvious WordPress answer, a block editor, is lane two per CLAUDE.md section 3 and is not contracted.
- **US-22-02.** The natural WordPress route to editable home sections is the block editor, which CLAUDE.md section 3 records as lane two and not contracted. The contracted route has to be a bespoke section manager, and that should be confirmed with Mustafa before the build rather than discovered in sprint 10.
- **US-22-04.** Does the translation plugin translate term meta, not only term name and description. P-006 tested product, variation and attribute taxonomy data and did not test term meta, so a probe is needed before US-22-04 is accepted.
- **US-22-05.** Whether a collection is a taxonomy or a post type is undecided, and the choice changes both the ordering storage and how the translation plugin registers it.
- **US-22-06.** P-010 names US-22-06 and has not been run. It is blocked until a storefront with real navigation, a mega menu, a footer and Arabic content exists, so the CoreX Stable claim for the header, nav and footer is untested and this story cannot reach proved until it runs.
- **US-22-07.** AC 1 says editable without code. Whether the stock WordPress page editor satisfies that, or whether the client expects a curated component set, matters because a block editor is lane two. Confirm at the Stage 1 walkthrough rather than assuming either reading.
- **US-22-08.** AC 2 reads as a component assembly editor. The only contracted way to deliver it is the section manager built for SSC-02 pointed at a campaign page template, because a block editor is lane two per CLAUDE.md section 3. If the client expects a block editor at the Stage 1 walkthrough that is Change Control, MS-CHG-2026-014, and not absorbed scope.
- **US-22-09.** P-006 does not measure translation quality and did not test the free alternatives, so it justifies the 107 USD a year line item without proving it is the cheapest way to satisfy FIX-04. PL-01 is still undecided in plugins.json.
- **US-22-09.** AC 3 needs a definition of what counts as missing content for the bespoke content areas, and no probe covers whether the plugin dashboard reports them once they are registered or whether Mizzey writes that report.
- **US-22-10.** The draft versus published content store is architecture shared with US-22-11 and with every editable area in this epic. It should be designed once before US-22-02 is built in sprint 10, or the sections get built twice.
