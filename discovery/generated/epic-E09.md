## Risks

**US-09-05, Explicit carrier status mapping.** P-012 is the reason this story exists and it proved the case. The Bosta WooCommerce plugin 4.5.7 ships a mapping table that maps state 45 to completed and state 46 to completed as well, grouped as "Finished successfully", while only 45 sets a delivery date. Two distinct terminal outcomes collapse into one Woo status. The plugin ships NO legend for the state codes anywhere in its source, so what 46 means cannot be established from the integration at all. That absence is precisely what SHIP-14 exists to fix, and it makes this story build rather than the claimed partial: there is no carrier mapping to extend, only a dormant one to replace.

**US-09-06, Returned to origin is never Delivered.** P-012 settled both halves and refuted the feared one. WooCommerce 11.1.0 ships eight order statuses and none is returned to origin, so the status itself must be registered: build. But the feared silent Delivered does not happen today, because in handle_status_update the call to map_bosta_state_to_wc_status is commented out, so the plugin never changes order status from a webhook and only records meta. Driving the handler with state 46 on a processing order left it processing. The real exposure is the dormant table: whoever enables it inherits 45 and 46 both becoming completed, which is exactly what AC 2 forbids. The direction recorded in DECISIONS.md is to leave the plugin mapping disabled and write the Mizzey mapping explicitly.

**US-09-07, Cash on delivery reconciliation.** Section 7 row 11 is exact: Woo marks a cash on delivery order paid on completion, so collected and remitted are the same thing and the distinction this story contracts does not exist. Build. The DECISIONS.md entry on ENT-10 already commits a delivered_at column as contractual for exactly this reason, because outstanding remittance cannot be aged or chased without knowing when collection happened. No probe covers this story directly, so reasoned rather than proved; P-018 is adjacent and relevant, since it showed date_paid and date_completed are the only queryable milestones and neither is dispatch or delivery.
